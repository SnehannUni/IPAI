# IPAI – Interpretable Planning for AI

**flowviz** makes the plans of AI agents interpretable before they run.

Animated, abstract flow diagrams that show **what happens, how, and how everything is connected**: from a button click through queues, databases and external services to the answer. The diagrams are meant for people who do not program, and they are generated by an LLM.

```
LLM writes   flows/topic.flow.json   →   flowviz validate   →   flowviz build   →   animated HTML page
             (boxes, arrows,              (errors + rules)       (one file,
              steps, states)                                      works offline)
```

## Quick start

```bash
node bin/flowviz.mjs validate examples/*.flow.json
node bin/flowviz.mjs build examples/k8s-bugfix.flow.json -o out/k8s-bugfix.html
npm test
```

No dependencies, just Node ≥ 20.

## Structure

| Path | Content |
|---|---|
| `docs/RULES.md` | **Rules** for abstraction, layout, step order, explanations and UI features (R1–R16), plus how to present bugs and fixes |
| `docs/FORMAT.md` | Reference of the JSON format (flow spec) |
| `src/viewer.html` | Viewer template (design, animation, simple/technical, views, before/after) |
| `src/layout.mjs` | Grid layout and automatic arrow routing (used by the viewer and the validator) |
| `src/validate.mjs` | Checks specs for errors and rule violations, including arrows through boxes, overlapping labels and cut-off texts |
| `src/build.mjs`, `bin/flowviz.mjs` | Builds a self-contained HTML file, command line |
| `examples/` | Templates: normal flow with a failure case, bug + fix |
| `.claude/skills/flow-diagram/` | Skill that lets Claude Code generate diagrams on its own |
| `flows/` | Generated specs: 10 real postmortems (Cloudflare, CrowdStrike, GitHub, Facebook, Roblox, Slack, Knight Capital, Sentry) created by agents without prior knowledge. They also serve as regression tests |
| `test/` | Validator and build tests, plus a run of the viewer through every step of every spec |
| `prototypes/` | The first hand-built drafts |

## Building blocks in one sentence

Six box types (trigger, step, storage, external service, result, screen) in zones (Frontend │ Backend │ External), connected by arrows with verbs. Solid means "waits", dashed "runs alongside", red "error", green/blue "new/changed". Every step is a sentence plus an explanation, and the state is visible in the boxes (checklists, chat bubbles, waiting slots, meters, menus).
